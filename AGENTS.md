## Code structure
The cuBNM program is structured into two components. First, the Python frontend provides the user interface via an application programming interface (API) and a command line interface (CLI), implements optimization and performs evaluation of simulations on Central Processing Unit (CPU) or Graphics Processing Unit (GPU). Python code is located in the `src/cubnm` directory. Second, the core backend executes parallel simulations efficiently on the GPU or CPU. Given the simulation configuration and parameters received from the Python component, it calculates simulated BOLD, state variables, functional connectivity (FC) and functionaly connectivity dynamics (FCD), and returns them to the Python component. The core consists of: (i) a C++ subcomponent that runs simulations and FC/FCD calculations on CPUs, while also acting as a bridge between Python and CUDA, and (ii) a CUDA subcomponent, that initializes arrays on GPUs, manages host-device memory transfers, and performs simulations as well as FC/FCD calculations on GPUs. C++ code is located in the `src/ext` directory. Headers (including some implementation) are located in the `include/cubnm` directory.

The Python API has four main modules:
- `cubnm.optimize`: Contains the `BNMProblem` class and the `Optimizer` family of classes. In typical workflows, these are the primary user-facing classes.
    - `BNMProblem` specifies a brain network model (BNM) optimization problem by defining the model type, network (nodes and their connectivity), free parameters (including their ranges, as well as the homo- or heterogeneity of regional parameters), simulation settings (e.g., duration, integration step, BOLD TR), and model evaluation metrics.
    - `Optimizer` includes `GridOptimizer` and `PymooOptimizer` family of classes (e.g., `CMAESOptimizer`). An optimizer is attached to a `BNMProblem` and (iteratively) tunes its parameters to minimize the cost function. This module also includes `batch_optimize()`, a function which enables performing multiple evolutionary optimizations in batch on a single GPU.
- `cubnm.sim`: Includes `SimGroup` and its model-specific subclasses (e.g., `rWWSimGroup`). `SimGroup` characterizes the network, simulation configuration, and parameters for a group of simulations that are intended to be run in parallel. In typical workflow, a `SimGroup` is created when a `BNMProblem` is instantiated, and users typically do not interact with it directly. `SimGroup.run()` calls `cubnm.core.run_simulations`, which is a backend function that runs simulations on CPU or GPU and returns simulated BOLD, state variables, FC/FCD and noise array. The outputs are passed to `SimGroup.score()` to compute the goodness-of-fit terms.
- `cubnm.datasets`: Contains loaders for the example data, such as structural connectomes, empirical BOLD, FC and FCD, as well as heterogeneity maps.
- `cubnm.utils`: Includes utility functions, notably GPU-accelerated Python functions for calculation of FC, FCD, $FC_{corr}$, and $FCD_{KS}$.

The implementation of specific BNM models is generated by `codegen/generate_models.py`. This script uses mako templates to generate the C++ and CUDA code for the specific BNM models, and the Python code for their corresponding `SimGroup` class.

`src/ext/core.cpp` acts as the bridge between the Python and core (C++/CUDA) components. It contains the implementation of the `run_simulations` function, which is the main function that runs the simulations and returns the results to the Python component. The typical flow of inputs is from user to `<Model>SimGroup` either directly or through `BNMProblem` and `Optimizer`, and then to `core.run_simulations`. `run_simulations` itself mainly acts as a dispatcher, and would run `model->run_simulations_cpu()` or `model->run_simulations_gpu()` depending on the simulation configuration. Here `model` is a pointer to the model class, which is a model-specific derived class of `BaseModel` (defined in `include/cubnm/models/base.hpp`). Ultimately, `model->run_simulations_cpu()` or `model->run_simulations_gpu()` would call `_run_simulations_cpu()` or `_run_simulations_gpu()` respectively, which are defined in `src/ext/bnm.cpp` and `src/ext/bnm_gpu.cpp` respectively. These functions are the actual implementations of the simulations and FC/FCD calculations. These functions and their downstream functions are templated on the model type. The CPU and GPU implementations should often be kept in sync, so that any changes to one are reflected in the other.

## Code style guidelines

In Python code:
- Do not use type hints.
- Do not write helper functions for trivial and small tasks, and opt for inline functions instead.

## Testing instructions

- Avoid running tests.
